# Contributing to La Compagnia della Ghironda

Thank you for your interest in contributing. This document describes the development workflow, code standards, and review process.

---

## First-time onboarding (read this first)

This repo is a **single-page brochure for an Ultima Online guild** but it's tooled at production-SaaS standards intentionally (see [README.md § Sull'identità di questo repository](README.md)). New contributors regularly hit non-obvious decisions documented here. The five things to internalize before touching code:

1. **Level B pure-CSS architecture**: JS does NOT manage graphics. Visual state is CSS-declarative (`:has()`, `view-timeline`, `scroll-timeline`, `@supports`). Adding `classList.toggle` or `setAttribute('aria-*')` to drive visuals is a regression. JS is permitted only for plumbing: deferred-CSS loader, Web Vitals telemetry, Service Worker registration, `sw.js` itself.

2. **100% per-file coverage AND 100% Stryker mutation**. Every `js/**/*.js` and `sw.js` carries hard gates. Don't propose lowering thresholds; either add a test that closes the gap or add `// Stryker disable` / `/* istanbul ignore */` with a documented reason that future maintainers can audit.

3. **Browser support floor**: Chrome 115+ / Firefox 134+ / Safari 26+ for `view-timeline`. Don't relax this with polyfills — graceful CSS fallback is the documented behaviour. Same floor for `:has()` (which we already shipped pre-floor).

4. **GitHub Actions are SHA-pinned with version comments**: `actions/checkout@de0fac2e... # v6.0.2`. IDE extensions may flag SHA pins as "version not pinned" — false positive, ignore. Supply-chain hardening is the reason.

5. **Documented trade-offs persist**: see `[Unreleased]` section of [CHANGELOG.md](CHANGELOG.md) for "trade-off accettati". `aria-current` is not written by JS (CSS can't write attributes); mobile nav stays open after anchor click (HTML popover was tried in Apr 2026 and rejected because the spec puts popovers in top-layer, conflicting with the desired drawer-below-header UX). These are choices, not bugs.

When in doubt, run `npm run lint` (includes `npm run lint:docs` which catches references to entities removed in past refactors).

## Development Setup

```bash
git clone <repo-url>
cd La-Compagnia-della-Ghironda
npm install          # installs dev dependencies and husky hooks
npm run serve        # dev server on http://localhost:8000
```

Node `<!-- AUTO:ENGINE_NODE -->>=24.0.0<!-- /AUTO -->` and npm `<!-- AUTO:ENGINE_NPM -->>=11.0.0<!-- /AUTO -->` are required (see `engines` in `package.json` — enforced via `engine-strict=true` in `.npmrc`; the project also pins Node 24 in `.nvmrc` and in every CI workflow's `NODE_VERSION` env).

### Dependency pinning policy

`devDependencies` are pinned with `~` (allow patch updates only) by default — Renovate / Dependabot opens a PR for every minor and our CI matrix verifies the bump before merge. Four packages are **pinned to an exact version** because a silent patch update has been historically disruptive:

| Package                                                                  | Why exact                                                                                                   |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `prettier`                                                               | Format output is the diff. A patch that changes whitespace would re-format every tracked file.              |
| `eslint-config-prettier`                                                 | Couples directly with `prettier`; must move in lockstep to avoid rule conflicts.                            |
| `cross-env`                                                              | Build-chain bridge for `NODE_ENV`; an unintended behavioural change would silently corrupt builds.          |
| `eslint-plugin-no-unsanitized` / `eslint-plugin-security` (where pinned) | Security rule semantics — a patch that re-classifies a finding from `error` to `warn` would relax the gate. |

If you bump any of the four, run `npm run test:all` and inspect the diff — the bump is intentional only when zero tracked files re-format and zero new lint findings emerge.

## Workflow

1. **Branch** from `main`: `git checkout -b feat/your-feature`
2. **Develop**: run `npm run build` once to populate `.deploy/`, then `npm run serve` (livereload). Edit source under `css/`, `js/`, `index.html`, `sw.js` — never edit `.deploy/` (gitignored, regenerated by every build).
3. **Build** before committing: `npm run build` regenerates `.deploy/` and refreshes any `AUTO:` doc-marker that drifted. Commit the marker updates alongside your code change.
4. **Test**: `npm run test:all` must pass (unit + lint + E2E across 3 browsers)
5. **Commit** using [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `perf:`, `style:`, `docs:`, `test:`, `chore:`
6. **Push** — the pre-push hook runs `npm run test:fast` (unit + lint, no e2e) automatically

### Quick checks during development

```bash
npm run test:unit       # Jest unit tests + coverage
npm run test:lint       # HTMLHint + Stylelint + ESLint
npm run test:e2e        # Playwright across 3 browsers
npm run test:visual     # Visual regression only
npm run test:visual:update  # Regenerate baselines after intentional UI changes
```

## Code Standards

### JavaScript

- **No framework, no runtime dependencies** — vanilla JS only
- Pure-plumbing surface (Level B): only `js/main.js`, `js/modules/{logger,vitals}.js`, `sw.js`. JS must NOT touch graphical state — every visual transition lives in CSS (`:has()`, `view-timeline`, `scroll-timeline`, `@supports`).
- Magic numbers UI-side belong in `css/1-variables.css` as custom property. Breakpoint values inside `@media` queries are CSS-spec-blocked from referencing custom properties — duplicate verbatim across the four CSS files that need them (see CSS-ARCHITECTURE.md).
- Feature-detect every browser API before using it
- Wrap browser-only code in `try/catch` only at system boundaries (PerformanceObserver type-not-supported, sendBeacon failure, SW fetch error) and call `devWarn` on errors
- `/* istanbul ignore */` comments only for branches structurally unreachable from jsdom (e.g. `serviceWorker` registration, deferred-CSS loader, defensive guards documented as such)
- ESLint must pass with zero warnings: `npm run lint:js`

### CSS

- Mobile-first: base styles for mobile, media queries override for larger viewports
- All values use CSS custom properties from `css/1-variables.css`; no hardcoded colors or sizes
- Layer order: `1-variables → fonts → 2-reset → 3-typography → 4-header → 5-hero → 6-sections → 7-responsive → 8-print`
- Critical CSS (above-fold) goes in files that build-css.js includes in the inline bundle; deferred CSS goes in `3-typography` and `6-sections`
- `prefers-reduced-motion` must be respected for any new animation
- Stylelint must pass: `npm run lint:css`

### HTML

- One `<h1>` per page; no heading-level gaps
- Every `<img>` needs `alt`, `width`, and `height` attributes
- Decorative images use `aria-hidden="true"` with empty `alt`
- New nav items must also get a BreadcrumbList position in the Schema.org JSON-LD

## Testing Requirements

| Type   | Command               | Must pass                                                                             |
| ------ | --------------------- | ------------------------------------------------------------------------------------- |
| Unit   | `npm run test:unit`   | 100% per-file coverage (statements, branches, functions, lines)                       |
| Lint   | `npm run test:lint`   | Zero warnings                                                                         |
| E2E    | `npm run test:e2e`    | All 3 browsers (Chromium, Firefox, WebKit)                                            |
| Visual | `npm run test:visual` | Baselines must match (regenerate with `--update-snapshots` after intentional changes) |

New features require new tests. Bug fixes require a regression test.

## Build Pipeline

Round 20 (option B production-grade): the build writes exclusively under `.deploy/` (gitignored on `main`). The `.deploy/` directory is force-pushed to the orphan `gh-pages` branch by `.github/workflows/deploy.yml` on every push to `main`. Source `index.html`/`sw.js` ship as pure templates (placeholder CSP hashes, empty inline-CSS markers, `CACHE_NAME = 'ghironda-PLACEHOLDER'`); the build materialises real values into the deploy copies.

```
Source files (main branch)
  → build:css + build:js (parallel)
  → build:assets       (mirror fonts/, images/, sw.js, manifest, .well-known/, LICENSE → .deploy/)
  → build:sitemap      (deterministic <lastmod> from git log → .deploy/sitemap.xml)
  → build:cache-bust   (composite SHA-256 over 10 inputs → ?v=HASH in .deploy/index.html + CACHE_NAME in .deploy/sw.js)
  → build:csp          (SHA-256 hashes of inline <script>/<style> → CSP meta in .deploy/index.html)
  → build:strip        (remove every HTML comment from .deploy/index.html except CSS:BEGIN/END markers)
  → size-report + audit:performance  (MUST stay within budget — exit 1 on overrun)
  → docs:numbers       (sync AUTO markers in tracked docs/configs against fresh build)
```

Never commit hand-edited bundle files (none are tracked). Always run `npm run build` and commit any AUTO-marker drift it produces.

## Visual Regression

Baseline screenshots live in `tests/e2e/visual.spec.js-snapshots/` and are committed. After intentional UI changes:

```bash
npm run test:visual:update   # regenerates baselines for all 3 browsers
git add tests/e2e/visual.spec.js-snapshots/
git commit -m "test: update visual baselines for <change description>"
```

## Commit Message Format

```
<type>(<scope>): <short description>

[optional body]
[optional footer: Breaking Change or issue reference]
```

Types: `feat`, `fix`, `perf`, `style`, `refactor`, `test`, `docs`, `chore`, `ci`

Examples:

```
feat(nav): add keyboard shortcut to open mobile nav
fix(hero): prevent image overflow on 320px screens
perf(css): defer section typography to reduce TBT
test(e2e): add visual regression for footer on tablet
```

Commits are linted by commitlint on every `git commit`. Non-conforming messages are rejected.
